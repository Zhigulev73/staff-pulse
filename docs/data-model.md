# Модель данных

## Контракт API: `GET /api/org-tree`

Плоский массив узлов:

```ts
interface OrgNode {
  id: string;
  name: string;
  parentId: string | null; // null у корневых узлов (дивизионов)
  headcount: number; // собственная численность узла, без потомков (целое ≥ 0)
  budget: number; // собственный бюджет узла в рублях, без потомков (≥ 0)
  performance: number; // эффективность 0..100
  updatedAt: string; // ISO-8601
}
```

Заголовки ответа: `ETag: "v<версия>"`, `Cache-Control: no-cache`. При `If-None-Match`,
совпадающем с текущей версией, сервер отвечает `304 Not Modified` без тела.

Клиент валидирует ответ схемой `orgNodeSchema` (`client/src/shared/api/schema.ts`).
Нарушение контракта (нет поля, `performance: 150`, не массив) — ошибка запроса с
описанием первых проблем, а не тихо искажённые данные.

Мок-данные: 4 дивизиона × 3–4 отдела × 2–4 команды, ≈60 узлов, ровно три уровня.
Генератор детерминирован (seed), поэтому набор одинаков при каждом запуске.

## Дерево

`buildModel(nodes)` в `client/src/shared/model/orgModel.ts`:

1. Индекс `Map<id, TreeNode>`, где `TreeNode = OrgNode & { level; children[] }`.
2. Один проход: узел с известным `parentId` попадает в `children` родителя, остальные —
   в `roots`. Узел с неизвестным `parentId` становится корнем: битая ссылка не должна
   молча выкидывать данные.
3. Обход в глубину от корней проставляет `level` (1 — дивизион, 2 — отдел, 3 — команда)
   и порядок `order` — это порядок строк таблицы по умолчанию.

Сложность O(n), глубина не ограничена.

## Агрегация

Для каждого узла агрегат включает **сам узел и всех потомков**:

```
totalHeadcount(v) = v.headcount + Σ totalHeadcount(c), c ∈ children(v)
totalBudget(v)    = v.budget    + Σ totalBudget(c)
weighted(v)       = v.headcount·v.performance + Σ weighted(c)
avgPerformance(v) = weighted(v) / totalHeadcount(v)   (0, если численность 0)
```

Средняя эффективность взвешена по численности: отдел из 90 человек с оценкой 100 и
команда из 10 человек с оценкой 0 дают 90, а не 50.

Считается за один post-order проход (сначала дети, потом родитель) — O(n).
`weighted` хранится в агрегате явно, чтобы пересчитывать среднее для одного узла из
готовых агрегатов детей без обхода поддерева (это основа инкрементального пересчёта
на этапе live-обновлений).

### Когда считается

`getOrgModel(nodes)` мемоизирует модель через `WeakMap` по ссылке на массив узлов.
Пока кэш react-query возвращает тот же объект, модель не пересобирается: сортировка,
фильтр, выбор строки и раскрытие веток к пересчёту не приводят. Новая ссылка появляется
только при реальном получении новых данных.

`rowsFromModel(model)` даёт плоские строки таблицы `{ id, name, level, totalHeadcount,
totalBudget, avgPerformance }` в порядке обхода дерева и мемоизирован по ссылке на модель.

## Таблица

Строка таблицы — агрегат узла (см. выше), уровень и название. Столбцы: Подразделение,
Уровень, Всего сотрудников, Бюджет суммарный (`12 345 678 руб.`, `Intl.NumberFormat('ru-RU')`),
Средняя эффективность (целое, взвешенное среднее).

Сортировка (`sortRows`) стабильная: равные значения сохраняют порядок дерева; названия
сравниваются `Intl.Collator('ru', { numeric: true, sensitivity: 'base' })`. Фильтр
(`filterRows`) — регистронезависимое вхождение подстроки в название.

## Live-патчи

### Контракт SSE: `GET /api/org-tree/events`

`Content-Type: text/event-stream`. События (в `data` — JSON):

| Событие  | `id`  | Данные                                      | Когда                                                     |
| -------- | ----- | ------------------------------------------- | --------------------------------------------------------- |
| `hello`  | —     | `{ version, etag, replay }`                 | сразу после подключения                                   |
| `patch`  | `seq` | `{ seq, nodeId, changes, updatedAt, etag }` | при каждом изменении узла; при досылке — по порядку       |
| `resync` | —     | `{ version, etag }`                         | клиент прислал `Last-Event-ID`, но история уже недоступна |
| `ping`   | —     | `{ t }`                                     | heartbeat каждые 15 с                                     |

```ts
interface OrgPatch {
  seq: number; // монотонный номер = версия стора после применения
  nodeId: string; // изменённый узел
  changes: Partial<{ headcount: number; budget: number; performance: number }>; // абсолютные значения
  updatedAt: string; // ISO-8601
  etag: string; // ETag снимка после патча (тот же формат, что у GET)
}
```

Значения в `changes` абсолютные, а не дельты — патч идемпотентен: повторное применение
(например, GET уже вернул новое значение, а следом пришёл патч) ничего не ломает.

Переподключение: клиент передаёт последний полученный `seq` в `?lastEventId=`
(эквивалент заголовка `Last-Event-ID`). Сервер держит кольцевой буфер из 200 патчей:

- если все патчи после `lastEventId` в буфере → `hello { replay: true }` и досылка;
- иначе (буфер вытеснен, сервер перезапущен) → `hello { replay: false }` + `resync`.

Клиент валидирует каждый патч схемой `orgPatchSchema`; невалидный кадр отбрасывается,
соединение не рвётся. `seq`, пришедший не следующим по порядку, означает потерю —
клиент делает один полный рефетч.

### Применение патча на клиенте

`applyPatch(cache, patch)` (`client/src/shared/model/applyPatch.ts`):

1. Находит узел; если его нет — патч игнорируется. Если значения не изменились —
   обновляется только `etag`.
2. Создаёт новый массив узлов, в котором заменён **только** объект изменённого узла
   (`{ ...node, ...changes, updatedAt }`); остальные ссылки те же.
3. Вызывает `patchModel(prevModel, changedNode)` и регистрирует результат как модель
   нового массива, поэтому `getOrgModel(nextNodes)` не строит дерево заново.
4. Возвращает `touchedIds` (узел + предки) и `changedFields` — из них выводятся ключи
   ячеек для подсветки.

### Инкрементальный пересчёт агрегатов

`patchModel` (`client/src/shared/model/patchModel.ts`) идёт по цепочке от изменённого
узла к корню и на каждом шаге пересчитывает агрегат **из собственных полей узла и уже
готовых агрегатов его детей** (`aggregateFromChildren`):

```
для v в [узел, parent(узел), …, корень]:
  agg(v) = own(v) + Σ agg(c), c ∈ children(v)      — дети НЕ обходятся, берутся из Map
```

Так пересчёт стоит O(глубина × ширина), а не O(n). Клонируются только узлы цепочки,
`children` предков получают новый массив с заменённой ссылкой, соседние поддеревья, их
агрегаты и строки таблицы остаются теми же объектами. Тест `patchModel.test.ts`
сверяет результат с полной пересборкой на 300 случайных патчах.

### Подсветка

Ключ ячейки — `nodeId:поле`. Для патча подсвечиваются: в дереве — изменённые поля узла
(`headcount`, `performance`); в таблице — агрегатные столбцы узла и всех предков,
на которые поле влияет: `headcount` → «Всего сотрудников» и «Средняя эффективность»,
`budget` → «Бюджет суммарный», `performance` → «Средняя эффективность». Запись живёт
1.5 с, анимация — CSS `@keyframes` с перезапуском через React-key (см. ADR-006).
