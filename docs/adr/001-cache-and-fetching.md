# ADR-001: Слой загрузки и кэширования данных

## Статус

Принято (этап 1).

## Контекст

Требования задания: запрос к `/api/org-tree` идёт через слой кэширования со stale time
5 секунд; лишние запросы исключаются (stale-while-revalidate или аналог); запрос
корректно отменяется при размонтировании; кэш инвалидируется только при реальном
изменении данных; невалидный ответ — ошибка.

## Решение

1. **TanStack Query** как слой кэширования. Один ключ `['org-tree']`, значение
   `{ nodes, etag }`. `staleTime: 5000`, `retry: 1`, рефетч по фокусу/реконнекту выключен.
   `queryFn` получает `AbortSignal` — отмена при размонтировании достаётся бесплатно.
2. **ETag + If-None-Match.** Сервер версионирует данные, клиент отправляет ETag прошлого
   ответа. На `304` `queryFn` возвращает прежний объект из кэша, поэтому ссылки не
   меняются и производные структуры (модель, строки) остаются мемоизированными.
   Так «инвалидация только при реальном изменении» выполняется на уровне протокола,
   а не по таймеру.
3. **zod-схема** на границе: ответ парсится в типизированный `OrgNode[]`, ошибка схемы —
   `InvalidResponseError` с перечнем первых проблем, попадает в обычное состояние ошибки.

## Альтернативы

- **Самописный кэш на useEffect + Map.** Нет зависимости, но отмену запросов, гонки при
  быстром перемонтировании, дедупликацию параллельных подписчиков и повторные попытки
  пришлось бы писать и тестировать вручную — риск ошибок выше пользы.
- **SWR.** Покрывает stale-while-revalidate, но точечное обновление кэша из live-канала
  (`setQueryData` с функцией-обновлением) в react-query удобнее и лучше типизировано.
- **Cache-Control: max-age вместо ETag.** Браузерный кэш неуправляем из кода: нельзя
  различить «данные не менялись» и «данные обновились», а именно это нужно для точечной
  инвалидации.

## Последствия

- Зависимость `@tanstack/react-query` (~13 КБ gzip).
- Кэш живёт вне React-дерева (`queryClient`), поэтому live-обновления (этап 3) смогут
  писать в него напрямую через `setQueryData`, не поднимая состояние по компонентам.
- Значение в кэше содержит `etag`; компоненты читают `data.nodes`.
