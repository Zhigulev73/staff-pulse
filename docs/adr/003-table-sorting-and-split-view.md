# ADR-003: Аналитическая таблица — сортировка, фильтр, split-view

## Статус

Принято (этап 2).

## Контекст

Требования: столбцы Подразделение / Уровень / Всего сотрудников / Бюджет суммарный /
Средняя эффективность; суммы включают потомков, среднее взвешено по численности;
сортировка по любому столбцу, двойной клик — обратная; фильтр по названию в реальном
времени с дебаунсом 250 мс; клик по строке выделяет узел в дереве; переключатель
«Дерево / Таблица» или split-view от 1280px; агрегация считается один раз и
мемоизируется.

## Решения

### Источник строк

Строки — `rowsFromModel(model)`: плоский список в порядке обхода дерева в глубину,
мемоизирован по ссылке на модель. Таблица не считает ничего сама: сортировка и
фильтр работают над готовыми строками (`sortRows`, `filterRows` — чистые функции
с тестами).

### Порядок по умолчанию и сортировка

- Пока пользователь не выбрал столбец, строки идут **в порядке дерева**: отступ по
  уровню читается как иерархия, дивизион сразу над своими отделами.
- **Клик** по заголовку — сортировка по столбцу по возрастанию. Если столбец уже
  активен, направление не меняется: иначе два клика, из которых состоит двойной,
  сбивали бы его.
- **Двойной клик** — обратить направление.
- Сортировка **стабильная** (при равенстве сохраняется порядок дерева), названия
  сравниваются `Intl.Collator('ru')`, направление объявлено через `aria-sort`.

Альтернатива «клик переключает asc → desc → без сортировки» привычнее, но противоречит
явному требованию про двойной клик; выбранная схема делает оба жеста предсказуемыми.

### Фильтр

Поле ввода контролируемое, значение в фильтр попадает через `useDebouncedValue(…, 250)`.
Ввод остаётся мгновенным, пересчёт списка — не чаще раза в 250 мс. Счётчик
«Показано N из M» с `aria-live="polite"` сообщает результат без визуального поиска.

Фильтр не подтягивает предков совпавших строк: колонка «Уровень» и отступ дают
достаточный контекст, а сохранение предков ломало бы счётчик и сортировку.

### Split-view и переключатель

От 1280px обе панели видны одновременно (grid 5fr / 7fr), переключатель скрыт
через тот же медиазапрос — он не должен «ничего не делать». Уже 1280px показывается
одна панель по выбору; обе остаются смонтированными (`display: none`), поэтому
состояние фильтра, сортировки и раскрытых веток не теряется при переключении.

### Синхронизация выбора

`selectedId` живёт в `App` и передаётся в оба компонента (controlled). Выбор из
таблицы дополнительно раскрывает предков узла (`reveal`) и прокручивает строку дерева
в видимую область — узел не может остаться выделенным внутри свёрнутой ветки.

## Последствия

- Сортировка и фильтр — локальное состояние таблицы: они не влияют на дерево и не
  должны подниматься выше.
- При переходе к live-обновлениям строки будут заменяться точечно (по ссылке на
  модель), а сортировка/фильтр пересчитаются `useMemo` по новой ссылке `rows`.
