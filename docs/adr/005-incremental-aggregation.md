# ADR-005: Один источник правды и инкрементальный пересчёт агрегатов

## Статус

Принято (этап 3; мемоизация модели заложена на этапе 1).

## Контекст

Задание: агрегация считается один раз после загрузки и мемоизируется; live-патч
применяется без полного рефетча; пересчёт агрегатов — только для затронутого узла
и его предков; обновлённые ячейки подсвечиваются.

Соблазн — завести для live-данных отдельную мутируемую модель рядом с кэшем
react-query. Тогда появляются два источника правды: кэш устаревает после первого
патча, любой рефетч перестраивает всё с нуля, а компоненты должны знать, откуда
брать «настоящие» данные.

## Решение

### Кэш react-query — единственный источник правды

Патч применяется в кэш через `setQueryData` (`applyPatch`): новый массив узлов, где
заменён только объект изменённого узла, плюс новый `etag` из патча. Компоненты
по-прежнему читают только `useOrgTree()`.

### Производная модель мемоизируется по ссылке на данные

`getOrgModel(nodes)` хранит модель в `WeakMap<OrgNode[], OrgModel>`. Пока кэш
возвращает тот же массив, модель не пересобирается — ни при сортировке, ни при
фильтре, ни при выборе строки. Это и есть «считается один раз после загрузки»:
без `useMemo` в компонентах и без ref-ов, которые приходится синхронизировать.

### Патч регистрирует модель инкрементально

`applyPatch` знает и прежний массив, и новый, поэтому вызывает
`patchModel(prevModel, changedNode)` и регистрирует результат для нового массива.
`patchModel`:

1. клонирует изменённый узел и его предков до корня (только их);
2. для каждого пересчитывает агрегат из собственных полей и **уже готовых**
   агрегатов детей (`aggregateFromChildren`) — без обхода поддеревьев;
3. соседние поддеревья, их агрегаты и строки таблицы сохраняют объектную
   идентичность.

Вычислительная сложность — O(глубина × число детей на уровне), а не O(n).
`Map` индексов копируются поверхностно (O(n) указателей, без вычислений) — это
цена неизменяемости прежней модели, которая ещё может быть на экране.

Корректность подтверждена тестом: 300 случайных патчей подряд, после каждого
инкрементальная модель сравнивается с полной пересборкой.

### Подсветка

`applyPatch` возвращает затронутые id и изменённые поля; из них выводятся ключи
ячеек: собственные поля узла (дерево) и агрегатные столбцы узла и предков (таблица),
причём только те, на которые поле влияет (бюджет → суммарный бюджет; численность →
всего сотрудников и среднее; эффективность → среднее). См. [ADR-006](006-cell-flash.md).

## Альтернативы

- **Отдельная live-модель на ref-ах.** Даёт O(глубина) без копий, но два источника
  правды, мутации во время рендера и отключение правил линтера. Отвергнуто.
- **Полный `buildModel` на каждый патч.** При 60 узлах незаметно, но буквально не то,
  что требует задание, и не масштабируется.
- **Пересчёт агрегатов на сервере и передача готовых сумм.** Убирает логику с
  клиента, но патч раздувается до размера цепочки предков, а клиент всё равно должен
  уметь считать агрегаты для первого рендера.

## Последствия

- `shared/model` — чистые функции без React, полностью покрытые unit-тестами.
- Строки таблицы для нетронутых узлов — те же объекты, что и до патча: React
  перерисовывает только изменившиеся.
- `WeakMap` не удерживает старые массивы: как только react-query отпускает прежний
  снимок, его модель собирается сборщиком мусора.
